## Why now

publish, moderation, auth").

## 0A. Premise challenge

- **The stated want is the owner's insight, not a user feature.** The P3 was
  written as a public library: accounts, browse, fork, publish queue,
  moderation (generic-TODOS.md "What:"). The owner's actual ask is narrower: "I
  want to see what people build". Those are different products. A library
  serves users and needs users to ask for it; the P3's own 2026-11-04 note says
  "no user asks for a library yet".
- **The privacy rule stays the default.** Seeing a layout means it leaves the
  browser. The only way that stays inside the approved rule is the user
  choosing to send it, layout by layout. Analytics must not do it silently.
- **What a layout carries.** A v1 link has no free text (shareLink.ts:9-11,
  "Piece ids do not travel (S3-2: no free text in a link)"): part codes,
  joins, positions. No name, no title, no message. So a sent layout holds no
  personal data unless the sender adds some, which v1 cannot carry.
- **Do-nothing cost:** the owner keeps guessing what people build. Every other
  priority (which parts to measure next, which sets to add) stays a guess.

  submissions in D1 with a pending status, Turnstile or a honeypot instead of
  accounts, an owner-only approval route (ziscus, djpardis/form, a DEV write-up).
  [ziscus.pages.dev], [github.com/djpardis/form], [dev.to/piyaklabs/comments-on-a-static-blog-no-backend-no-login-all-cloudflare-18b]
- Layer 3: a gallery's cost is moderation, and moderation exists because
  strangers see each other's content. If nothing is shown to strangers, there
  is nothing to moderate.

The P3 as written: accounts, browse, fork, publish queue, moderation. ## Outcome (2026-11-05)

The owner proposed a narrower version during the question: a public page of
builds, published by users, approved by the owner, shown without attribution.
Their rule: any legal risk, scrap it. The risks found (not legal advice):

1. A publish request carries the sender's IP address, which GDPR treats as
   personal data; the audience includes children (COPPA counts IP addresses
   and device identifiers on a site aimed at children).
2. Showing a user's layout needs their licence to show it.
3. Approving every item makes the owner the publisher; an EU hosting service
   also owes a contact point and a notice-and-action route (DSA).
4. The open IP P1 (part data, naming) would reach a wider public surface.

**Decision: scrapped.** No public page, no inbox, no library. The P3 moves
to the shelved section with this reason. The server-free "email it to the
maker" variant was offered and not taken.

Review depth was strategy-only and the only approach decision was declined, so
Review Sections 1-10 have no plan to review: nothing is built.
