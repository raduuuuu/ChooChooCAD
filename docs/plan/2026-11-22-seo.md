## 0A. Premise

The real problem: a parent who searches for help with wooden track cannot
land here, because the site offers a search engine eight thin pages and no
pictures. The outcome wanted: visits that arrive from search. Doing nothing
costs nothing today and leaves the app with one known user. The plan attacks
the pain directly (pages and pictures that match what people type), with one
proxy risk: nobody has yet confirmed the site is indexed (P8), so that check
is in the core.

## Core (held scope)

One pull request, 1.3.1 to 1.3.2 (patch: wording and tooling, nothing new to
do). It is pull request 1 in the order below; pull request 0 is this plan.

- C1. Layout titles and descriptions say the piece count in the words people
  type: "Stadium: a 10-piece wooden train track layout".
- C2. The sitemap carries a date per address. The date is when that page's
  content last changed, kept in the layout's own data, never the build time:
  every merge deploys, and a date that moves on every deploy tells a search
  engine nothing and makes the test depend on the clock.
- C3. Structured data (schema.org, as JSON-LD): `WebApplication` on the home
  page; `ItemList` on each list page; `BreadcrumbList` on each layout page
  (home, the list, the layout).
- C4. The list page orders layouts by piece count and says the count first.
- C5. Owner only: register the site with the search engines' consoles and
  read whether it is indexed. The file or DNS record that proves ownership
  ships in a follow-up once the owner has it.

## Section 11. Design

- **What a visitor sees first, on a layout page:** the name with the piece
  count, the picture, the pieces list, the button into the planner, then one
  line linking to the why page.
- **Sizes page on a phone: open.** A table with four columns does not fit
  320 px. It needs stacked rows or a sideways scroll that is plainly
  scrollable. Pending, owner: design review.
- **Picture text.** Each PNG holds words (name, count). The same words must
  be in the `alt` text and on the page, since a picture's text is unread by
  a screen reader.
- **The three verdict drawings** on the why page must not tell exact, joint
  play and miss apart by colour alone; each carries its word, as the app's
  verdict does.
- **Copy rule:** no screen direction in any new sentence (DESIGN.md rule 7).
- States: static pages have no loading, empty or error state. A count with
  under four layouts has no list page; `/layouts/` still shows its layouts.
- Flow: search result ▶ layout page ▶ "Open in the planner" ▶ editor with
  that layout ▶ change it. And: search result ▶ sizes or why page ▶
  `/layouts/` ▶ a layout page.
- Recommended before pull request 2: `/plan-design-review` on the picture's
  look and the sizes table.
