## 0A. Premise

- **Real goal:** the layout on screen should look like the track on the floor, so a
  parent and child recognise their own pieces. That is fidelity, not decoration.
- **It changes no verdict.** Every earlier review ranked it behind wrong-answer fixes.
  Those are now mostly done or waiting on measurements, so this is a fair time.
- **Risk:** detail that is invented (not measured) makes the app look more certain
  than it is. The approved rule answers it: outlines from photos, heights estimated
  and marked.
- **Do-nothing cost:** the 3D view stays a clean diagram; nothing breaks.

## Scope Challenge

**What already solves each sub-problem (read in the code):**
- Collide-only boxes plus one drawn box: the vault does exactly this (`decorBoxesOf`, engine/data/library.ts:94-108: two walls and a roof `{ solid: true, draw: false }`, and a footprint `drawOnly(shape)`).
- 3D skips collide-only boxes: `if (b.decor && !b.decor.draw) continue;` (engine/src/view3d/mesh.ts:478). No other reader of `draw`.
- Collisions read `solid` only: `segments.filter((sg) => sg.decor?.solid !== false)` (engine/src/graph/overlap.ts:219).
- 2D draws every solid box: `drawnFlat = (b) => b.decor?.solid !== false` (engine/src/graph/render.ts:304). So a solid, undrawn hall still appears in 2D exactly as now, and a non-solid drawn box never does.
- The mirror is known per box in render.ts (`const mirror = piece.turn === 'right' ? -1 : 1`, render.ts:158) but not passed into `decor` (render.ts:177); ShapeFrame.at has no mirror (mesh.ts:486).
- The 3,000-triangle budget already covers every built-in part, SS included (engine/test/decorated.test.ts:165-179).
