## Step 0

**0A Premise.** The 3D view is now detailed enough (station, tunnel, crossing,
elevated station) that the one grey fill hides what the pieces are: the real
elevated station is a green roof, beech posts, a red lift and crank. The pain is
recognition ("is that my station?"), not correctness: verdicts do not change.
Doing nothing costs nothing functional; the 3D stays a grey model.

**0B Leverage.** Shapes already carry a `noun` per box (engine/data/library.ts
`decorBoxesOf`), so a colour can key off the shape, not new data. The scene is
merged per material (eng D20); colour per shape means either per-vertex colour
in the one structures buffer or one buffer per paint. Tokens come from CSS at
runtime (`tokenColors`), so paints would be new tokens in `tokens.css`, each
with its measured contrast (DESIGN.md rule 5).

**The channel, engine to app (R2):** `paint` is copied onto each DecorBox the way `noun` is (library.ts:90), and onto each Segment's `decor`. `buildScene` writes, beside `structures.solid`'s positions, a per-vertex paint index (`solidPaint: Uint8Array`, 0 = unpainted) and the list of token names it indexes (`paints: readonly string[]`). Both paths stamp it: the slab/box path (mesh.ts:590-600) and the shape path through the Pen (the canopies and the arch). In build mode the placed piece's vertices get 0, the next piece's keep their index (`isNextPiece`, mesh.ts:532). `paint` holds the token name with its leading `--` (e.g. `'--track-fill'`, `'--paint-roof'`). The app's `tokenColors` reads, at mount, every token named by any built-in shape's `paint` (one static palette exported beside the seeds, so a station added while 3D is open is already resolved; O2), whatever its prefix (a missing one says so and draws in `--ink`, as now), converts it with `new Color(token)`, and writes a linear `color` attribute; index 0 is written as `--slab-side`, so an unpainted structure and a placed station in build mode look as they do today. `flat()` gains an opt-in `vertexColors` option (with a white base), used only for the `structures.solid` mesh; every other mesh keeps its plain colour.

**The halo (R5, O1, O3):** one helper draws a `--paper` line 4px wider (2px each side) under a given line, same depth settings, one render order below it. Callers: the selection outline (`SELECTED_PX + 4`, order 7 under 8), every `--fail` line (level lines and the slab overhang outline), and the next-piece outline in build mode.

**Mirroring:** paint follows the shape, so a station flipped to the other side (F) keeps each part's paint (mesh.ts:552 mirrors the shape, not the colour).

## Review sections (/plan-ceo-review, SELECTIVE EXPANSION, implementation-ready)

### 1. Architecture

```
  structureSeeds.ts STATION ──decor[].paint ('--paint-roof', '--track-fill', ...)
        │
  library.ts decorBoxesOf ──copies paint onto each DecorBox (like noun, :90)
        │
  render.ts ──Segment.decor.paint (bodies)
        │
  mesh.ts buildScene ──structures.solid + solidPaint (Uint8Array) + paints (token names)
        │      ├─ slab/box path (:590-600) stamps the box's paint
        │      ├─ shape path: the Pen stamps the shape's paint (canopy, arch)
        │      └─ build mode: placed piece → 0, next piece keeps its index (:532)
        │
  Viewer3D.tsx tokenColors ──reads each named token, `new Color()`, linear `color` attribute
        └─ flat({ vertexColors: true }) on structures.solid only; selection: paper halo (order 7) + ink (8)
```

Data paths: happy (a painted shape → its token's colour); nil (no `paint` → index 0 → `--slab-side`, today's look); empty (`paints` empty → every vertex `--slab-side`, the attribute still written, one code path); error (a named token missing from CSS → `tokenColors` logs it and draws `--ink`, as it does today for any token). No new state machine: build mode's placed/next split already exists. New coupling: seed data names CSS tokens as strings; justified because tokens are the design system's one source (DESIGN.md:3-5), and a test checks every named token exists. Scale: one Uint8 and three floats per structure vertex; the Elevated station is a few thousand vertices. Rollback: revert the PR; no data or saved layout changes (paint is seed data, not stored).
Findings: none needing a decision. One check is directly required by R1/R4 and added to Tests: every token named by a `paint` exists in tokens.css.
