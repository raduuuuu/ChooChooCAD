## Step 0

### 0A. Premise

The 3D viewer's two surviving reasons (N2, 2026-10-07): stacked levels are hard
to read flat, and the meshes come for free from parametric part data. The pain
it serves is the physical build: "which piece goes next, and where". A viewer on
its own only serves legibility; build mode is what touches the floor. Do-nothing
cost: two-level layouts stay readable only through the shadow and raised-look
cues, and `assemblyOrder` stays an engine function nobody can see.

### 0B. Existing code leverage

| Sub-problem | Reuse |
|---|---|
| Where every piece is, including bent loops | `renderGraph` + `bendRender` segments (`render.ts`, `bendPose.ts`) |
| Heights | `level`, `rise`, `highAtStart` on each segment; rise and plank from `calibration.ts` |
| Plank cross-section, groove | `TRACK_PROFILE` / per-part `plankThicknessMm`, `grooveWidthMm` (`engine/data/brio.ts:85`) |
| Step order (for X1, not used here) | `assemblyOrder(graph, segments)` (`assembly.ts`) |
| Part names and codes (for X1, not used here) | `getPart`, `shortCode` |

## Accepted scope

1. **Mesh data in the engine** (`engine/src/view3d/`): from the same `drawn`
   render the canvas uses (`bendRender` over `renderGraph`, so bent loops are closed) build plain arrays per piece:
   plank body with the groove, at `level × rise`, ramps sloped between their two
   levels and high end per `highAtStart`, multi-road pieces as their roads, buffer
   stops with their beam. No Three.js import, so it is tested in the node project.
2. **A lazily loaded viewer** (`app/src/Viewer3D.tsx`): Three.js imported with a
   dynamic `import()`, so it lands in its own chunk; orbit, zoom, reset view.
3. **A 2D/3D switch** in App; 2D stays the default; the choice is not a new
   editing mode (the 3D view is read-only).
4. **Verdict marks in 3D (X3, D4 + D8)**: all six mark kinds the canvas draws (gaps,
   refused joins, overlaps/clashes, level mismatch, third level, adapter), from the
   same App data. Their height rule is pending (S5).
5. **Table slab (X6)**: the saved table (`loadTable`) as a slab under the track,
   placed the way the 2D outline places it ("Centred on track").

## NOT in scope
